## 한 줄 요약

네이버 플레이스는 **"전국민이 보는 검색 결과 = 가게 정보의 사실상 표준"**. 별점·리뷰 수·TV 출연·메뉴·예약·페이가 한 카드에 다 들어가 있는 *완성형 카탈로그* — 그러나 사용자가 *원하는 걸 검색어로 표현*해야만 작동하는 **검색 엔진 모델**이다.

---

## 핵심 결론 3가지

1. **정보 밀도는 압도적, 그러나 *변별력*은 한계.** 신당동 맛집 검색 결과 상위 10건 평균 리뷰 수 **2,000~5,000**. 별점은 4.0~4.5 천장. → 사용자가 *수십 개 카드를 비교해 골라야* 함.

2. **상단 = 광고 슬롯이 명시적.** "광고" 라벨이 카드 상단에 붙어 있음. 당근과 다른 점은 *유료 노출이 사용자에게 투명함*. 실력·평점이 아닌 *돈으로 사는 가시성*이 검색 시작점.

3. **"가게 발견"은 네이버가 표준화했지만 "골목 큐레이션"은 여전히 부재.** 동네골목이 비집고 들어갈 슬롯은 *"검색어 못 만드는 사용자"* — "오늘 비 와서 따끈한 거" 같은 자연어 맥락은 네이버 검색이 못 받음.

## 4축 비교 — 네이버 vs 당근 vs 동네골목

### 축 1. 주체 (Who)

| 항목 | 네이버 플레이스 | 당근 동네업체 | 동네골목 v1 |
|---|---|---|---|
| 사용자 규모 | 한국 검색 표준 (네이버 점유율 60%대) | 4,300만 가입자 | (파일럿) |
| 동네 단위 | 동(읍·면·동) | 동(읍·면·동) | **골목** (가게 50개로 정의) |
| 가게 등록 | 무료 + 광고 유료 | 무료 + 광고 유료 | 큐레이터가 직접 선정 |

### 축 2. 거래 (Transaction)

네이버 플레이스의 거래 인프라:
- **네이버페이** (결제), **톡톡** (채팅), **예약** (실시간), **주문**, **배달**, **쿠폰**
- → *거의 모든 거래 흐름이 네이버 안에 닫혀 있음*. 사장님 입장에서 가장 강력한 lock-in.

**시사점**: 동네골목이 실제 결제·예약을 안 가지므로 *거래 인프라 측면에서는 정면 경쟁 불가*. 차별화는 *"발견 단계의 대화 UX"*에서만 가능.

### 축 3. 정보 (Information)

신당동 맛집 검색 결과 상위 10건 직접 관측:

| 가게 | 카테고리 | 별점 | 리뷰 수 | 특징 |
|---|---|---|---|---|
| 우육미 | 한우 (광고) | - | 3,242 | TV 생방송투데이 |
| 하숙집 | 한식주점 (광고) | - | 58 | 신규 |
| 연해장 | 한식 (예약) | - | 4,581 | TV 핸썸가이즈, 알림받기 쿠폰 |
| 상무초밥 왕십리점 | 초밥·롤 | - | 5,657 | 주간 인기 메뉴 표시 |
| 치소우다이닝 신당점 | 일식당 | - | 2,465 | 네이버 예약 시 쿠폰 |
| 왕게수산 킹크랩 신당동직영점 | 킹크랩요리 | - | 599 | - |
| 종점 | 떡볶이 (24시간) | **4.38** | 2,124 | 신당동 떡볶이타운 |
| 바다약방 신당점 | 생선회 | - | 311 | 알림받기 시 들기름 아이스크림 쿠폰 |
| 마복림할머니집떡볶이 | 떡볶이 | **4.19** | **1.4만** | TV 2TV생생정보 |
| 앤드위치 | 샌드위치 | - | 979 | "잠봉뵈르의 풍부한 매력" |

**관전 포인트**:
- **리뷰 수 분포가 당근의 *후기 수*(수십~수백)보다 *2~3 자리 높음***. 네이버는 *전국민 인덱스*, 당근은 *동네 인덱스*.
- 별점이 *카드에 항상 표시되지 않음* (광고/네이버페이 카드는 별점 가림). → 사용자가 별점을 일관되게 비교하기 어려움.
- "주간 인기 많은 메뉴", "알림받기 쿠폰", "TV 출연" 등 *바이어스 신호*가 풍부 — 사용자가 결정에 활용할 단서 많음.

### 축 4. 관계 (Relationship)

- **이웃 ↔ 가게**: 알림받기(팔로우) 메커니즘. 당근의 "단골"과 유사.
- **가게 ↔ 가게**: 거의 없음. 같은 카테고리 내 *경쟁 관계*만.
- **이웃 ↔ 네이버**: 네이버페이 적립·할인 → *플랫폼 lock-in*.

당근과 가장 큰 차이: **네이버는 "이웃 커뮤니티" 자산이 약함**. 네이버 카페·블로그가 분리되어 있고, 플레이스 자체에 *동네 잡담* 슬롯은 없음.

## 동네골목과의 차별점 (한 단락)

> **네이버 플레이스가 "전국민이 보는 가게 카탈로그"라면, 동네골목은 "골목 사정 아는 친구"다.** 네이버에서 신당동 맛집을 검색하면 카드 70개 + 별점 + 리뷰 5,000건 + TV 출연 이력 + 메뉴 가격이 한꺼번에 쏟아지지만, *그 중에 뭘 고를지는 사용자가 직접 비교*해야 한다. 동네골목에선 *"오늘 비 와서 따끈한 거"*라고 말하면 비서가 *50개 중 3개*를 골라준다. 네이버는 정보의 양으로 이긴 검색 엔진, 동네골목은 정보의 *해석·조합*으로 차별화하는 대화 비서. **네이버를 쓰는 사람은 *결정해야 할 변수*가 늘어나고, 동네골목을 쓰는 사람은 *맥락만 던지면* 변수가 줄어든다** — 이것이 두 서비스가 같은 유저의 다른 시점에 공존할 수 있는 이유다.

## 한계 (솔직 보고)

1. **네이버 플레이스는 iframe 구조** — Chrome DevTools MCP가 메인 지도와 별개로 `pcmap.place.naver.com` iframe을 봐야 함. 이번엔 iframe까지 들어가긴 했으나 가게 상세 페이지(`m.place.naver.com`)는 모바일 뷰여서 데스크톱 캡처가 어색.
2. **별점·리뷰의 *진짜 분포*** 미검증 — 상위 10건만 본 결과로 일반화하기 어려움. 페이지 5까지 다 보면 더 정확한 그림 가능.
3. **광고 vs 자연 노출 비율** — 검색 결과 상단 2건이 "광고"였음. 비율이 페이지마다 일정한지, 키워드마다 다른지 미확인.
