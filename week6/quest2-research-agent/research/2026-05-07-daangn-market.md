## 한 줄 요약

당근은 **"4,300만 가입자 × 동(洞) 단위 트래픽"으로 동네 거래·생활·홍보를 한 그릇에 담은 슈퍼앱**이다. 동네 비즈니스의 "노출"은 사실상 당근이 표준화했지만, **이웃이 가게를 *발견하는 경로*는 여전히 검색·광고·후기 리스트 — *대화형 추천 / 골목 큐레이션* 슬롯은 비어 있다.**

---

## 핵심 결론 3가지

1. **주체 측면 — 당근의 "동네"는 *행정동*이지 *골목*이 아니다.** 동네 인증·광고 타겟팅·검색 필터 모두 읍·면·동 단위. 같은 동 안에서도 "골목 단위 큐레이션"은 사용자가 직접 후기를 뒤져야 함. → **"우리 골목" 단위 큐레이션은 무주공산.**

2. **거래·정보 측면 — 당근은 *목록형 발견 엔진*, 동네골목은 *대화형 발견 엔진* 슬롯.** 당근의 동네업체는 "검색 → 카테고리 필터 → 평점·후기·단골 수 정렬 → 가게 카드"로 작동. *AI 비서가 맥락 듣고 가게 3~5개 골라주는* 흐름은 부재. **당근 비즈프로필 데이터(4,300만 명이 본 가게 자기소개·쿠폰·후기)는 풍부하지만, 그것을 LLM 컨텍스트로 *씹어 추천하는 레이어*는 당근이 아직 안 함.**

3. **수익 모델 측면 — 당근의 매출은 *광고*(디스플레이·검색 광고). 동네골목은 *광고 없는 큐레이션* 포지셔닝 가능.** 당근 사장님이 *돈 내고* 노출되는 동안, 동네골목은 *돈을 안 내도* 골목에 진짜 있는 50개 가게가 AI 비서로 자연스럽게 등장. **"광고 없는 동네 비서"** 차별화가 의미 있는 메시지가 됨.

## 축 1. 주체 (Who) — 누가, 어떤 단위로 모이는가

### 1-1. 사용자 규모와 정체성

| 지표 | 값 | 출처 |
|---|---|---|
| 서비스 가입자 | **4,300만** | business.daangn.com (2026-01 기준) |
| 월간 이용자 (MAU) | **2,000만+** | business.daangn.com (2026-01 기준) |
| 동네 인증 단위 | **행정동(읍·면·동)** | 메인 검색 필터 ("송도동", "역삼동", "물금읍" 등) |
| 글로벌 진출 | **Karrot Canada / US / Japan** | daangn.com 푸터 |

> 4,300만은 한국 인구의 80% 이상. 사실상 *전 국민이 가입한 동네앱*. 이 규모에서는 "신규 사용자 확보"가 차별화 포인트가 안 됨. **차별화는 "이미 당근 쓰는 사람이 *동네골목을 추가로 쓰는 이유*"에서 와야 함.**

### 1-2. 동네 인증 메커니즘

- **GPS 기반 동네 인증** + **매너온도** (사용자 평판) + **머신러닝 게시글 분석** (안전·이상 거래 탐지)
- 가게(사장님) 측은 **비즈프로필 무료 등록** — 동네 단위 노출, 광고는 별도 유료
- 비즈프로필 가게 카드 표준 항목: **상호명 / 카테고리(설렁탕집·돼지고기·피자 등) / 자기소개 / 평점(0~5.0) / 후기 수 / 단골 수 / 동(洞) 위치 / 쿠폰 여부**

### 1-3. 사장님(공급자)의 진입 장벽

당근 비즈프로필은 *진입은 쉽고 노출은 광고로 해결*하는 구조:

| 단계 | 비용 | 핵심 |
|---|---|---|
| 비즈프로필 등록 | **무료** | 가게 정보·소식·쿠폰 발행 |
| 디스플레이 광고 | 유료 (간편/전문가 모드) | 중고거래 홈 등 다양한 화면 |
| 검색 광고 | 유료 | 검색 결과 상단 노출 |
| 추가 도구 | 일부 유료 | 견적 받기 / 예약 관리 / 상품 판매 / 포장주문 / QR오더 |

**관전 포인트**: 광고 없이 비즈프로필만 등록해도 "동네 검색 결과"에는 노출되지만, **사장님 입장에서 "유의미한 단골 확보"는 사실상 광고비 투입이 필요한 구조** — 이것이 당근의 매출 엔진이고, 동네골목이 비집고 들어갈 빈틈이기도 함.

| 카테고리 | 거래 성격 | 동네골목과의 관계 |
|---|---|---|
| **중고거래** | C2C 물건 (당근 시작점, 트래픽 핵) | 무관 |
| **부동산** | 직거래 (방·원룸·전세) | 무관 |
| **중고차** | 직거래 | 무관 |
| **알바/과외/레슨** | C2C 일거리 | 무관 |
| **동네업체 (비즈프로필)** | **B2C 가게 발견·홍보** | **★★★ 직접 경쟁 영역** |
| **동네생활** | C2C 동네 커뮤니티 (질문·소식·맛집 정보) | ★★ 보완 가능 (동네골목은 거래 유도, 당근은 잡담) |
| **모임 / 카페** | C2C 관심사 모임 | ★ 약한 인접 |
| **당근알바 / 당근페이** | 결제·일거리 인프라 | 동네골목 v2 영역 |

### 2-2. 동네업체(비즈프로필) 거래 흐름 — 사용자 시점

당근에서 "동네 가게 발견" 흐름:

```
1. 검색창에 "맛집" / "에어컨청소" 등 입력
2. 행정동 필터 적용 (예: 신당동)
3. 카테고리·평점·후기 수·단골 수로 직접 비교
4. 가게 카드 클릭 → 상세 페이지 → 채팅 / 쿠폰 / 예약
```

**한계**: 사용자가 "원하는 게 뭔지 검색어로 표현 가능"해야 함. **"오늘 비 와서 따끈한 거 먹고 싶은데 골목 안쪽에 좋은 데 있을까?" 같은 자연어 맥락은 당근 검색이 안 받음.**

### 2-3. 결제·정산

- **당근페이** (별도 자회사) — 송금, 채팅 결제, 가게 결제
- 비즈프로필 가게는 "상품 판매 / 채팅주문 / QR오더" 등 결제 도구 옵션
- 실거래 수수료 정책은 공개 페이지에서 명시되지 않음 — 비공개

## 축 3. 정보 (Information) — 어떤 정보가 흐르는가

### 3-1. 당근이 보유한 정보 자산

| 정보 자산 | 규모/형태 | 활용도 |
|---|---|---|
| **가게 자기소개 텍스트** | 비즈프로필 N십만 건 (자유 서술) | 검색·필터링·LLM 학습 잠재 데이터 |
| **이웃 후기·평점** | 가게당 수십~수백 건, 평점 4.0~5.0 분포 | 신뢰도 핵심 |
| **단골 수** | 가게당 30~800+ (관측 표본) | 당근 특유의 "팔로우" 신호 |
| **동네 커뮤니티 게시글** | 동네생활 (실시간) | 진짜 동네 이슈 reference |
| **동(洞) 단위 검색 트래픽** | 4,300만 × 행정동 분포 | 광고 타겟팅 핵심 |

### 3-2. 정보 흐름 비교

**당근**: 사장님이 입력 → 사용자가 검색·필터로 *꺼내옴* → 후기·단골이 *누적되는* 일방향 + 누적형
**동네골목 슬롯**: 사용자가 자연어로 맥락 던짐 → AI 비서가 50개 골목 가게 컨텍스트 + 후기·DB *조합해 골라줌* → 사용자가 "그러면 이 중에 매운 거 빼고" 같은 *대화형 절제·확장*

> **시사점**: 당근은 "정보의 양"으로 이긴 플랫폼. 동네골목은 "정보의 *해석·조합 방식*"으로 차별화 가능. **같은 가게 데이터를 LLM 컨텍스트에 얹어 대화로 꺼내는 레이어는 당근이 안 만들고 있음** (현재까지 공개된 한)— 이것이 v1 MVP의 정확한 슬롯.

### 3-3. 정보 신뢰성 메커니즘

| 메커니즘 | 당근 | 동네골목 v1 |
|---|---|---|
| 동네 인증 | GPS + 매너온도 | 없음 (로그인도 시뮬) |
| 가게 정보 검증 | 사업자번호 + 사장님 셀프 | **에디터/큐레이터 검증** (정적 50개) |
| 후기 누적 | 수십~수백 건/가게 | 없음 (v1) |
| 머신러닝 안전 검증 | 게시글 분석 | 없음 |

**솔직 평가**: v1 MVP 시점에서 "정보 신뢰성 인프라"는 당근이 압도. 동네골목은 *"50개로 좁힌 큐레이션 신뢰"*로 승부. → 작은 N의 강점을 메시지화해야 함.

## 축 4. 관계 (Relationship) — 사람들이 어떻게 연결되는가

### 4-1. 당근의 관계 모델

| 관계 종류 | 메커니즘 |
|---|---|
| **이웃 ↔ 이웃** | 매너온도, 채팅, 동네생활 게시글, 모임 |
| **이웃 ↔ 가게** | 단골(팔로우), 후기, 채팅, 쿠폰 |
| **가게 ↔ 가게** | 거의 없음 (브랜드프로필이 본사·지점만 묶음) |
| **이웃 ↔ 당근** | 매너온도 누적, GPS 인증, 추천 알고리즘 |

### 4-2. "단골" 메커니즘 분석

당근 비즈프로필의 핵심 관계 신호 = **단골 수**.
관측 표본 (검색어 "맛집" / 신당동·장안동·한남동 등):

| 가게 | 평점 | 후기 | 단골 | 동 |
|---|---|---|---|---|
| 팔각도 서울장안점 | 4.5 | 78 | **799** | 장안동 |
| 풍국면 장안점 | 4.5 | 40 | 245 | 장안동 |
| 야끼니꾸 청량 | 4.7 | 31 | 243 | 전농동 |
| 여기서 먹자 | 5.0 | 6 | 113 | 신당동 |
| 아노브 이태원본점 | 5.0 | 12 | 93 | 한남동 |
| 에이스버거 동대문 본점 | 4.8 | 50 | 59 | 용두동 |
| 9237 숯불구이 한양대점 | 5.0 | 48 | 41 | 행당동 |
| 샤브단 | 5.0 | 40 | 32 | 명륜4가 |
| 은설설렁탕 | 5.0 | 35 | 31 | 화동 |

**관전 포인트**:
- 단골 수와 후기 수는 *상관관계가 약함* — 후기 많아도 단골 적은 곳, 후기 적어도 단골 많은 곳 공존
- **평점 분포는 거의 4.5~5.0 천장형** — 변별력은 후기·단골 수가 함. → "평점 5.0"은 거의 의미 없음
- 사용자 입장에서 "어디 갈까" 결정 시 *단골 수가 진짜 신호*로 작동

### 4-3. 동네골목이 제안할 수 있는 관계

당근에 *없는 관계 슬롯*:
- **AI 비서 ↔ 사용자** (지속 대화 맥락) — 당근 검색은 stateless
- **골목 단위 묶음** — 당근의 동(洞)은 너무 큰 단위 (역삼동에만 가게 수천 개)
- **큐레이터의 추천 책임** — 당근은 알고리즘+광고, 동네골목은 사람이 고른 50개

## 동네골목과의 차별점 (한 단락)

> **당근은 "행정동 단위 × 4,300만 사용자 × 광고 매출"의 슈퍼앱이다. 동네골목은 "골목 단위 × 큐레이터가 고른 50개 가게 × 광고 없는 AI 대화 비서"로 정확히 반대 스펙트럼에 선다.** 당근에서 "신당동 맛집"을 검색하면 가게 카드 수십 개를 *직접 비교해 골라야* 하지만, 동네골목에서는 *"오늘 비 와서 따끈한 거 먹고 싶다"*고 말하면 비서가 골목 사정 아는 사람처럼 3개를 *대화로* 꺼낸다. 당근의 비즈프로필 데이터(가게 자기소개·후기·단골 수)는 *목록을 채우는 연료*지만, 동네골목에서는 *Claude의 컨텍스트 윈도에 통째로 들어가는 한 입짜리 골목 지식*이 된다. **"광고 없이 골목에 진짜 있는 가게만 대화로 꺼내주는 동네 비서"** — 이것이 당근이 *4,300만 규모 때문에 못 만드는* 슬롯이다.

## 한계 (솔직 보고)

⚠️ **이번 리서치는 *공개 웹페이지* 기반. 다음 주제는 추가 검증 필요:**

1. **당근 내부 추천 알고리즘** — 당근이 이미 "AI 추천"을 내부적으로 운영 중일 가능성 (검색 광고 모드의 "정밀한 타겟팅"이 LLM 기반인지 불명). → 당근 채용공고 / 당근 미디엄 기술 블로그 후속 검토 권장.
2. **단골 메커니즘 정확도** — 단골 수가 *진짜 재방문 빈도*와 연결되는지, 아니면 단순 팔로우 수치인지 모호. 사장님 인터뷰 / 운영자 글 추가 reference 필요.
3. **광고 단가** — 비즈프로필 무료지만 "유의미한 트래픽"의 광고비 규모 비공개. → 사장님 커뮤니티(블라인드, 자영업 카페) 정성 reference 필요.
4. **MAU 2,000만+의 *동네업체 사용 비중*** — 4,300만 가입자 중 실제로 비즈프로필을 *클릭하는* 비율은 미공개. *중고거래 트래픽이 동네업체로 얼마나 흘러가는지* 후속 검증 필요.
5. **모바일 앱 대비 웹의 한계** — 본 리서치는 daangn.com 웹 기준. 실제 트래픽 대부분은 앱이고, 앱 UX는 별도 캡처 필요. (다음 quest #2 후속에서 앱 emulation 또는 스크린샷 자료 활용)
